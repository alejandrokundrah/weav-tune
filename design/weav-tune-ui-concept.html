Frame: familiar by design

A brand-new, habit-first interface for the Weav-Tune player. The Liquid Glass identity stays on the floating chrome; structure, contrast and reachability follow what listeners already do. Every decision below maps to a behaviour learned from years of Spotify, Apple Music and YouTube Music — so the app feels obvious on first open, without a tutorial.

Design rationale / specification

Why this layout feels familiar

Radical layouts make people re-learn a music player they already know. So the skeleton is deliberately conventional — left rail for destinations, top-centre search, a persistent transport bar, content cards that play on click, and a bottom tab bar on mobile. The new work happens in the details: contrast, hierarchy, one accent, and reachability.

Before · what the current screen teaches us

Low contrast, small typeMuted grey nav labels on near-black fall below 4.5:1; secondary text sits around 11–12px. Reading the library takes effort.
Two competing navigation systemsThe top strip mixes search, "Browse", "New Tab", a hamburger and a three-dot menu next to a full left sidebar. Users cannot tell where "go somewhere" lives.
One accent used for everythingRed marks the logo, active state, play, liked heart and a player icon. When everything is salient, nothing is.
Inverted hierarchy"Good afternoon, MOONCRAFT" dominates while the actual album/artist and section labels are tiny; "Recently played" is clipped with no scroll affordance.
Tiny, ambiguous hit targetsIcon-only controls under 24px, no visible focus or pressed states, truncated titles with no tooltip or expansion.

Habit → design decision

Home resumes, then discoversHero greeting dwarfs the content it points at✓ Greeting as quiet context; "Jump back in" first, "Made for you" second, history third

Player never disappearsBottom bar present — this was already right✓ Kept verbatim: 72px bar, artwork + like + transport + progress + queue/lyrics, always visible
Queue and lyrics on the rightNo persistent queue or lyric state✓ 252px context panel, Up next / Lyrics tabs, closable and re-openable from the player bar

One accent only. Blue/cyan is reserved for actions and active states. Artwork supplies the colour; the chrome stays neutral. Dark theme uses the same palette inverted with a brighter accent for contrast.

Space, radius, motion

Grid 4px · spacing 8 / 12 / 16 / 24
Radii 8 controls · 12 cards · 16 frames · 999 pills
Targets ≥44×44 desktop · ≥48×48 mobile
Motion 160–240ms ease-out for state changes; 340ms spring for the player sheet; decorative glow is paused on prefers-reduced-motion
Glass blur(20px) saturate(170%) on chrome only — reading surfaces stay opaque

Accessibility checklist

✓

✓

✓
State is never colour-only (active pill, filled heart, tinted tab)
Handoff note. This prototype is a single self-contained HTML file with no external assets — the artwork is CSS-only, so it renders offline and in the preview panel. The shell maps 1:1 to the existing platform code: the left rail / topbar / content / context panel / player bar map to SideChrome.kt, the TopBar, HomeScreen.kt, the queue sheet and BottomChrome.kt in Compose; the mobile tab bar and expanding sheet map to SwiftUI TabView + .sheet, and to the React web player's existing flex/grid layout. Tokens are CSS custom properties at the top of this file and can be translated to Compose Color/Typography and SwiftUI Color assets directly. Suggested build order: tokens → persistent player → navigation shell → Home content → context panel → mobile sheet → accessibility pass.

Assumption: the new interface adopts the Weav blue/cyan Liquid Glass identity from the README, with light as the default and dark as a first-class variant. If you want to keep the red-accented dark look from your screenshot instead, that is a single token swap.
